## 1. GitHub、静态托管与 Publishable Key

GitHub 保存源码；CloudBase 静态网站托管连接 GitHub 后构建页面。数据库、登录、原图和奖励由同一个 CloudBase 环境处理。GitHub Pages 也可以提供静态页面，但不能独立保存跨设备数据；本项目默认以大陆访问为目标部署到 CloudBase 上海。

**本项目不需要 Publishable Key。** SDK 使用环境 ID 初始化，在后台自动建立匿名会话；普通使用者不需要操作登录。服务端允许此身份参与共享冒险，并用上传票据限制云存储写入。管理员使用账号密码登录，服务端再核对管理员角色。Publishable Key 是另一种公开资源访问方式，不是服务器管理密钥，也不必为了本项目创建它。

相关官方文档：[初始化与可选 accessKey](https://docs.cloudbase.net/api-reference/webv2/initialization)、[身份认证](https://docs.cloudbase.net/api-reference/webv2/authentication)、[静态托管](https://docs.cloudbase.net/hosting/web-hosting)。SDK 主版本 3 与控制台的“身份认证 V2”不是同一个版本编号；项目固定 JS SDK 3.10.1。

所有 DB 变更均通过 `quest-api`，禁止客户端直写。服务端从 CloudBase 可信上下文取 UID，不信任请求里的 UID 或 role。

画作流程：服务端准备上传票据及 `quest_uploads/grant-UID` 授权 → `upload-ticket` 再检查身份、当前票据、路径、大小与有效期，通过服务端 SDK 签发该路径的上传凭证 → 浏览器 PUT 原图至指定暂存路径 → 云函数检查归属、有效期、大小、SHA-256、真实图片格式和像素数 → 保存原图及 720px 内 WebP 缩略图 → 数据库事务提交作品与里程碑，关闭对应授权。每个 UID 同时只为一个待上传路径签发凭证，票据一小时过期。原图字节保持不变。相同文件禁止重复；同一请求重试只计数一次；并发提交旧进度会被拒绝。图片替换有版本校验，避免覆盖另一台设备的编辑。

存储安全规则不支持本项目原先使用的跨数据库 `get(...)` 表达式，云端会拒绝保存。`cloudbase/storage.rules.json` 现禁止所有客户端直接读写，正式文件仅由服务端处理；上传使用服务端 `getUploadMetadata` 返回的指定路径凭证，不向浏览器提供服务器密钥。已签发凭证在平台签名到期前可能重复写入同一暂存路径，不能即时撤销；票据失效、替换或完成后不再签发新凭证，正式提交仍检查身份、票据有效期、摘要及进度。本环境实测签名有效期 900 秒、合法 PUT 返回 200、篡改路径返回 403；迁移环境或升级 SDK 后需重新验证。

每个冒险只有 25 张作品；进度、奖励、最多 20 封信在一个有界文档中事务更新。角色、上传票据与旧版本归档独立保存。删除只允许最后一张，奖励历史保留，图片及元数据进入归档，不自动永久删除。

## 4. 管理员的一次性腾讯云部署设置

以下步骤仅由管理员完成，普通使用者不需要配置。需要你的腾讯云账号权限，本工程没有代替你完成授权或购买。匿名登录是后台自动连接能力，启用后不会向使用者显示登录表单。

1. 登录 [CloudBase 控制台](https://tcb.cloud.tencent.com/)，确认上述环境确实在 **上海**，使用文档型数据库与传统云存储。不要选择 PG/RLS 模式；如果现有环境只有 PG 模式，先停在这里，需调整适配而不是套用本规则。
2. 按控制台提示完成账号实名认证。查看现有套餐/额度是否已包含数据库、云函数、存储、静态托管；若出现购买或升级要求，先评估，不要自动开通收费选项。
3. 在身份认证 V2 → 登录方式/身份源启用“匿名登录”和“用户名/密码登录”。前者让普通冒险自动连接并参与，后者仅供管理员。关闭不需要的自助注册；没有角色的实名账号不能获得写入权限。
4. 在用户管理创建发起人账号，密码由你自己填写、保管。记下其 **UID**，不要使用邮箱、用户名或昵称代替 UID，不要给匿名用户管理员角色。无需为普通使用者创建账号。
5. 在安全来源/安全域名添加本地 `http://127.0.0.1:5175`（按控制台要求拆分域名及端口），以及最终托管 HTTPS 域名。不要使用 `*`。
6. 创建下列四个文档型集合；每个集合设置 `cloudbase/database.rules.json` 的规则（客户端读写都禁止）：`quest_state`、`quest_roles`、`quest_uploads`、`quest_archive`。
7. 云存储权限设置为自定义，粘贴 `cloudbase/storage.rules.json`（客户端读写均禁止）。合法上传凭证由函数校验票据后签发，只用于票据指定的暂存路径；无票据、过期、其他路径及他人票据不能领取凭证。正式原图及缩略图只能由云函数写。原图浏览通过服务端短时签名链接。
8. 部署 `quest-api` 云函数，配置见下一节。使用环境运行身份，不在代码或浏览器中配置 SecretId/SecretKey。给函数运行角色本环境文档数据库和云存储所需权限；不要开放 HTTP 免鉴权触发器。
9. 完成下面的数据初始化和管理员角色配置。在“云函数 → 权限控制”读取并备份现有规则，仅合并或更新 `quest-api` 为 `{"invoke":"auth != null"}`，保留原有 `*` 和其他函数条目。`cloudbase/functions.rules.json` 是只有本项目时的完整模板，不能覆盖其他业务配置。若控制台显示“鉴权设置 → 安全管控 → OPA 策略鉴权”，按文末新版入口说明操作，不要把 JSON 粘贴到 Rego 编辑器。函数调用允许已认证身份（包含自动匿名身份），拒绝无身份请求；管理员角色仍由函数校验。用控制台规则模拟器验证访客上传票据及管理员边界，再实际上传验收。
10. 开启已有静态托管能力，完成 GitHub 仓库访问授权与 SPA 配置。自定义域名、HTTPS 和域名备案按控制台要求由你完成；未配置前可先用控制台分配的测试域名验收。

安全规则传播可能有延迟，保存后再做规则验收。不能因为上传失败临时改成“所有人可写”。真实环境规则解释器、账号认证及运行角色权限必须在云端实测。

## 5. 初始化 0/25；导入真实两张作品

**不要用初始化操作覆盖已有记录。** 当前默认不导入测试图，不伪造两张作品。

```sh
npm run cloudbase:config
```

这个命令只生成 `.local/cloudbase-initial-state.json`，不会访问云端。在空环境的 `quest_state` 导入该 JSON，文档 ID 必须是 `main`。出现同名文档时停止，不覆盖。

在 `quest_roles` 中创建管理员文档，ID 使用你核对过的账户 UID。普通匿名使用者不需要角色文档：

```json
{ "_id": "发起人账号的真实UID", "role": "admin", "active": true }
```

角色只能通过受信任控制台管理。撤权将 `active` 改为 `false`；该账号下次请求立即拒绝写入。前端没有自助升级管理员入口。已有 hero 角色兼容保留，无需再分配。匿名身份始终不能获得管理员权限；管理员退出后可以继续普通冒险。

也可在受信任终端用临时云 API 凭据执行 `npm run cloudbase:init`：通过终端环境变量提供 `TCB_ENV`、`QUEST_CONFIRM_ENV`、`TCB_SECRET_ID`、`TCB_SECRET_KEY`，临时凭据还需 `TCB_SESSION_TOKEN`。环境确认值必须与目标 ID 完全一致。脚本只初始化空集合，不创建/授权账号。不要在聊天中发送凭据，不要加 `VITE_` 前缀，不提交到 Git。

登录网站发起人账号 → 冒险信箱管理 → 历史作品导入。按真实创作顺序导入两张原图及实际日期，成功后依次显示 1/25、2/25。第三张通过正常“继续冒险”上传后解锁第 3 关礼物；金额在亲手开启后才显示。

## 9. 备份与回滚

日常管理界面“导出元数据备份”包含作品信息、奖励历史、信件，不包含图片。完整备份使用受信任终端的临时云 API 凭据：

```sh
npm run cloudbase:backup
# TCB_ENV 指向待备份环境；命令只读云端，写入本机 cloudbase-backups/。
```

完整备份包含当前及归档画作的原图/缩略图、四个集合、来源环境、SHA-256 校验清单。备份时暂停编辑；若修订号变化，脚本报错并不生成完成清单。只有含 `manifest.json` 且所有图片校验通过的目录才算完整备份。把整个目录加密保存到独立介质；不要提交 Git。用户账号/密码由 CloudBase 身份服务管理，不在本备份中。

恢复只支持**另一个空环境**，不覆盖正式数据：

```sh
npm run cloudbase:restore -- /绝对路径/完整备份目录
```

设置新环境 `TCB_ENV`，`QUEST_CONFIRM_ENV` 必须相同；先创建四个空集合并配置拒绝客户端访问。脚本先验证全部本地文件，再上传图片并重写 fileID，在事务中恢复进度/奖励/信件/归档。不迁移账号权限及过期上传票据；在目标环境重新创建并核对账号、设置角色后再开放访问。恢复失败可能留下未引用图片，但不会删除来源或覆盖原数据。

前端回滚：部署上一个通过验收的 Git 版本产物，并保留相应资源。后端回滚：部署与当前数据库 schemaVersion 兼容的旧函数版本。数据库恢复：新环境完整恢复并验收，之后再切换前端环境 ID。不能直接将有数据的正式环境重置为 0。

旧 Sites 的源码、D1/R2 数据和部署未在本次接手中更改；本机不假定存在上一台电脑的 `../brush-quest` 目录。`README.sites.md` 是历史部署说明，不是当前 CloudBase 的启动方法。

## 10. 错误、安全日志及上线前检查

函数只记录 action、UID 的不可逆短摘要、成功/失败与错误码，不记录密码、令牌、信件、原图或签名 URL。控制台使用云函数请求日志定位失败。预期输入/权限错误返回中文说明，内部异常返回通用错误；不吞掉服务故障。前端无法从构建文件中获得服务端奖励金额配置或未解锁信件。

安全边界验收以实际 CloudBase 为准：数据库四集合全部客户端读写拒绝；云存储只允许当前票据指定路径；匿名及 hero 无法写正式目录、改角色、编辑信件、历史导入、登记发放或导出备份；admin 也只能通过校验后的云函数执行业务操作。共享冒险意味着任何打开网址的人都可参与同一份作品进度，并看到已解锁信件。

完整验收步骤见 [上线验收清单](docs/上线验收清单.md)。只有本地测试通过不能宣称腾讯云部署或跨设备同步已验证。

### 管理员排障：首次访问或自动连接失败

SDK 3.10.1 在浏览器没有登录凭据时，`getSession()` 会返回 `unauthenticated`。旧版前端在此处提前退出，未执行访客登录。本版本只针对这一状态建立匿名会话；已有账号会话保持不变，网络或权限错误仍会阻止请求。部署修复后的构建产物，并刷新页面；不要通过清空数据库或放宽安全规则解决。

若出现“暂时无法连接冒险世界”，由管理员在目标环境核对匿名登录已启用、当前网站域名已加入安全来源，并按控制台提示等待配置生效。错误码 `login_type_disabled` 表示匿名身份源未开启；不需要普通使用者登录。自动连接后若冒险服务仍不可用，继续核对 `quest-api` 云函数、四个集合及初始化记录是否已部署。若只能浏览不能上传，核对云函数和存储规则是否同时升级到本版本。

### 管理员排障：匿名认证成功后 `EXCEED_AUTHORITY`

先分别记录匿名认证与 `quest-api` 的 `state` 调用结果，不记录令牌或密码。认证 HTTP 200、函数调用 HTTP 403 / `EXCEED_AUTHORITY` 表示调用在权限层被拒绝，不能据此认定函数已部署、集合已创建或进度是 0。不要要求普通使用者登录，也不要通过开放数据库读写修复。

旧版函数权限入口使用 [官方函数安全规则](https://docs.cloudbase.net/cloud-function/security-rules) 与 `cloudbase/functions.rules.json`。只有本项目且没有其他业务规则时可使用完整模板：

```json
{
  "*": { "invoke": false },
  "quest-api": { "invoke": "auth != null" }
}
```

已有配置必须保留原有 `*` 和其他条目，仅合并 `quest-api`。不要改成全环境 `invoke: true`，也不要使用排除匿名身份的 `auth.loginType != 'ANONYMOUS' && auth != null`。

新版控制台可能将函数页的“鉴权设置”导向“环境管理 → 安全管控 → OPA 策略鉴权”。先读取表格视图及语法视图并备份完整配置；`cloudbase/gateway.rules.rego` 仅针对 SDK 实际使用的 `/v1/functions/quest-api`：允许已认证身份 POST 调用，显式拒绝无身份调用，不授予管理员角色，不放开数据库、云存储或其他函数。合并时只保留一行 `package authz.user`，保留已有规则，检查是否有冲突的 `deny`；不能直接覆盖其他业务策略。不要选择表单中的“所有用户（不限）”作为本项目的替代方案。

**本环境已获授权保存并回读 OPA，其他环境仍需语法校验和真实调用验收。** 官方说明保存后立即生效，且旧版网关鉴权向 OPA 的切换不可逆；正式保存前由环境管理员确认。此网关策略不替代仍然存在的函数级安全规则、存储规则或函数内角色检查。参考：[OPA 策略](https://docs.cloudbase.net/envconfig/authz-opa/intro)、[旧版迁移说明](https://docs.cloudbase.net/envconfig/authz-opa/migration)。

权限调整后必须重新用全新匿名身份读取状态。若返回函数不存在，先部署 `cloudfunctions/quest-api`；若集合缺失，核对后仅创建缺失集合并禁止客户端读写；若 `NOT_INITIALIZED`，先检查 `quest_state/main`，只有不存在才初始化 0/25。已有记录一律保留。随后分别验收上传票据、签名 PUT 暂存上传、函数完成处理和状态回读；遇到存储权限错误应定位对应策略和路径，不能放开整个存储桶。

本次实测：保存 OPA 后匿名调用仍为 403。官方 CLI 的 `DescribeResourcePermission`（`ResourceType: function`）读出原 `*` 为 `auth != null && auth.loginType != 'ANONYMOUS'`；保留这一默认项，仅合并 `quest-api.invoke = auth != null` 并回读后，全新匿名调用变为 HTTP 200。初始化前返回 `NOT_INITIALIZED`，在四个空集合中只插入缺失的 `main` 后返回 `role: hero`、0 张作品、revision 0。新版控制台入口并不意味着函数级规则已被取消；需要继续检查这层规则。
