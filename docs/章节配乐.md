## 资源与播放

- 七首录音由用户提供，原文件不修改。网页版本保留完整时长，使用 160 kbps / 44.1 kHz MP3，移除封面与原文件标签；总大小从 81,131,857 字节降为 39,514,689 字节。
- `public/audio/*.mp3` 纳入源码，Vite 原样复制到 `dist/audio/`。文件名包含内容 SHA-256 前 12 位，更换音频时使用新文件名并同步映射，避免旧缓存。无需外部音乐平台、CDN 或新的项目运行依赖。
- 仅在声音开启且用户首次点击/按键后创建当前曲目的媒体元素。`preload="none"`，使用原生媒体流式播放与 `loop`，不下载/解码所有曲目；静音或离开标签页立即暂停并释放请求，返回时从暂停位置续播。
- 媒体元素接入现有 Web Audio 混音链，共用音量与音效压低音乐功能。切换场景最多保留一条淡出轨；旧曲异步播放结果不覆盖新曲状态。减少动态设置不影响音乐偏好。
- 加载中和加载失败均在设置窗口显示，顶部声音按钮在加载中也可静音；失败不会假装成功或偷偷播放替代曲，下一次声音按钮/页面手势可重试。

## 部署与回滚

沿用现有上海 CloudBase 静态托管 `shuihenzao/` 前缀。先上传新增 `dist/audio/` 和哈希 JS 资源，回读核对字节、MP3 类型并记录 Range 分段请求的实际响应，再切换 `admin/index.html` 和 `index.html`。不要只上传 JS，否则曲目会 404。保留旧入口备份和全部旧资源，回滚时恢复旧 HTML 即可，不涉及数据库、云函数或存储权限。

当前 `webapps.tcloudbase.com` 默认域名实测：MP3 类型为 `audio/mpeg`，Range 请求仍返回完整 200 响应和 `Cache-Control: no-store, no-cache, must-revalidate, max-age=0`，虽然响应声明 `Accept-Ranges: bytes`。因此本次不宣称云端有效分段下载或缓存命中；播放只请求当前压缩曲目，恢复较后位置可能需要重新加载该文件。内容哈希文件名为以后复用缓存保留版本隔离，不改变现有托管设置。
